# Этап E: повторяемые проверки

Инструменты из [отчёта 21](../../../docs/modernization-audit/21-STAGE-E-QUALITY.md). Только синтетические данные, отдельная база PostgreSQL. Рабочие данные и рабочую базу не использовать.

## Матрица доступа

Обычный тест Django, входит в полный набор:

```
python manage.py test eventproject.tests.test_access_matrix
```

Таблицу «адрес × роль × метод» можно сохранить в CSV: `ACCESS_MATRIX_OUT=matrix.csv`.

## Репетиция миграций 0024 → последняя → 0024 → последняя

Нужен модуль настроек с отдельной пустой базой PostgreSQL (`DJANGO_SETTINGS_MODULE`):

```
python scripts/stage_e/migrate_rehearsal.py
```

Скрипт создаёт данные историческими моделями схемы 0024, затем после каждого перехода сверяет число мероприятий, заявок, участников и ссылок на файлы. Кроме того, после перехода вперёд проверяются:

- заполнение полей мероприятий;
- статусы;
- индекс `attendee_dateadd_idx`.

Журнал пишется в JSON, если задана переменная `REHEARSAL_OUT`.

## Сквозной сценарий «браузер → Django → PostgreSQL → файлы»

1. **Переменные окружения:**
   - `E2E_DIR` — рабочий каталог вне репозитория;
   - `E2E_DB_USER`, `E2E_DB_PASSWORD`, `E2E_DB_HOST`, `E2E_DB_PORT`, `E2E_DB_NAME` — отдельная база;
   - `E2E_FERNET_KEY` — синтетический ключ;
   - `POPPLER_BIN` — каталог Poppler для PDF.
2. **База:** `python scripts/stage_e/manage_e2e.py migrate`.
3. **Синтетические данные:** `python scripts/stage_e/manage_e2e.py shell -c "exec(open('scripts/stage_e/seed_e2e.py', encoding='utf-8').read())"`. Скрипт создаёт мероприятие, оператора и проверяющего, а в `E2E_DIR` кладёт файлы и `creds.json`.
4. **Серверы:**
   - Django: `python scripts/stage_e/manage_e2e.py runserver 127.0.0.1:18811`;
   - SPA: в `frontend` выполнить `VITE_BACKEND=http://127.0.0.1:18811 npx vite --port 18812`.
5. **Запуск сценария:** в `frontend` выполнить `E2E_DIR=... npx playwright test -c playwright.live.config.ts`. Используется установленный Chrome.

Сценарий проходит такие шаги:
- вход оператора;
- добавление участника со всеми полями, фото в JPG и сканом в PDF;
- поиск в реестре;
- превью файлов с сервера;
- отправка на проверку;
- очередь проверяющего: «Взять на проверку», «Допустить»;
- выгрузка новых записей;
- итоговый статус у оператора;
- ширина реестра на 390 px.

Архив выгрузки и снимки экрана сохраняются в `E2E_DIR/out`. Повторный запуск требует чистой базы, иначе сработает защита от дубля ИИН.
